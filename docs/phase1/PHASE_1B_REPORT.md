## 5. Unexpected Findings

1. **SLURM is installed, configured, and non-functional.** `scontrol --version`
   → `slurm 22.05.9`; `sbatch`/`srun`/`salloc` on PATH; `/etc/slurm/slurm.conf`
   present. But `scontrol ping` → **`Slurmctld(primary) at csrmaster is DOWN`**,
   and both `slurmctld` and `slurmd` are `failed`. Every surface check passes;
   the capability is absent. A `which sbatch` check would have misled the entire
   project.

2. **Disk, not VRAM, is the binding constraint.** `/data` at **99%**, ~82 GB
   free — the May report had shown 1.9 TB. Four months of shared use consumed
   it. `~/.cache` alone was already 24 GB.

3. **Six-decimal log formatting hid a real cross-machine difference.** Every
   logged step printed identically across machines; only full-precision
   `metrics.jsonl` revealed ~1e-7 divergence. Step 15 matched bitwise by
   coincidence, so checking one step could have "confirmed" the wrong answer.

4. **The cu124 index caps at torch 2.6.0**, verified by resolver error:
   *"Because only torch<=2.6.0+cu124 is available…"*. The approved plan
   therefore pins the server seven minor versions behind local.

5. **No supplementary groups at all** — `groups` → `rsoumyadeep` only. Docker is
   installed but unusable without sudo, and no Apptainer/Singularity exists.
   Containers are off the table entirely.

6. **The venv is 5.1 GB, dominated by bundled CUDA libraries** — `nvidia/`
   2.7 GB, `torch/` 1.5 GB, `triton/` 439 MB. On a 77 GB volume that is
   material.

## 6. Corrections / Bugs Discovered

**Three test failures after configuring the server, all investigated:**

**Two meant the test was wrong.** `test_no_hardcoded_absolute_paths` forbade
machine-specific paths anywhere under `configs/` — but `configs/env/` is by
design the single place such values may live. The guard forbade exactly what
the design exists to permit; it had passed in Phase 1A only because the file
held placeholders, so the rule had never been exercised against its intended
exception.

*Fix:* excluded `configs/env/` via an explicit list — **and closed the hole that
opened** by adding `test_machine_specific_paths_are_confined_to_env_group`,
which re-runs the scan with exclusions *off* and asserts every hit lies under
`configs/env/`. Widening the exclusion list can no longer widen the exemption
silently.

**One was a planned transition.** `test_server_paths_are_mandatory_and_unset`
asserted the paths raised `MissingMandatoryValue`. Its own docstring
pre-authorised the change: *"only once `scripts/server_probe.sh` has been run
and the values are backed by real output."* Condition met. The invariant moved
from "must be absent" to "must be real" — set, absolute, not a disguised
placeholder — plus two new tests (roots distinct; local config stays env-var
driven).

*Net effect: one test changed, three added.* The replacement invariants are
strictly stronger, which is the line between maintenance and misconduct.

**A hunch corrected mid-session.** On first inspection the CPU losses looked
identical across machines and I said so. Full-precision comparison showed ~1e-7
divergence. The initial statement was wrong; the corrected finding is in §4 and
in `PYTORCH_CONCEPTS`.

**Cosmetic:** `tests/test_config.py` arrived on the server via `scp` with CRLF
endings. Git normalised the committed content to LF; the working copy was
re-checked-out to match. No content impact.
